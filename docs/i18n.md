# Internacionalización (i18n)

## Stack

- `i18next` + `react-i18next` + `i18next-browser-languagedetector` (frontend)
- Plurales con `Intl.PluralRules` (cubre reglas complejas de pt/ru/ár)
- RTL preparado: `dir="rtl"` en `<html>` para idiomas árabes/hebreos

## Idiomas

| Fase | Idiomas |
|---|---|
| Lanzamiento (Fase 2) | `es`, `en`, `pt`, `fr` |
| Post-lanzamiento (Fase 5) | Cualquier idioma, vía módulo admin con IA |

Añadir un idioma = crear `frontend/src/locales/<iso>/` + código ISO 639-1. Nada más.

## Estructura

```
frontend/src/locales/
├─ es/{common,player,library,settings,ai,admin,billing,legal,errors}.json
├─ en/...
├─ pt/...
└─ fr/...
```

Namespaces separados para cargar por ruta (no todo el diccionario de golpe).

## Selección de idioma

`navigator.language` → `localStorage` → **perfil de usuario** (`user.language` en BD) → fallback `es`.

## Backend

- Los errores responden **códigos** (`error.code`); el frontend traduce el mensaje.
- Correos/avisos: plantillas por idioma del usuario.
- Documentos legales: es (original jurídico) + en; otras traducciones con nota "traducción de cortesía".

## Glosario de marca

Términos no traducibles ("Aura AI", "Phorocket", nombres de presets) definidos en `.agents/conventions.md` y consumidos por el módulo de traducción IA.

## Módulo admin (Fase 5)

- Cobertura: % de keys por idioma, faltantes por archivo.
- Gemini propone traducción con contexto de la key + glosario → cola de revisión → publicar.
